# long-task-orchestration (LTO)

> **一句话**：`agent-delegate` 的长程进阶版——ad 解决「单轮委派怎么跑通」，LTO 解决「多轮推到上线怎么判停」。专治**过度设计**和**长程失稳**。
>
> 它不是"更努力地干活"，是一套**"想多做一层就先过三道可证伪闸门"**的判停纪律：(a) 缺的那个具体信号 X 此刻真的不存在吗？(b) 真数据用你**预先承诺的阈值**证伪你了吗？(c) 用户拍板要做吗？——三道全过才许往下走。

LTO 是**纪律 skill**，不是能跑的库：它没有 import、没有进程、不"执行"任何东西。它被 agent 加载后**改变 agent 的决策行为**——把 agent 从"凭感觉觉得该抽象、信自己旧结论、health 200 就收工"，扳回到"亲核源码后敢否决任何一方（含自己）、机制真通电才算数"。

**选你的入口：**

- 👤 [我是人类，想理解它治什么病](#-给人类它治什么病凭什么有效)
- 🤖 [我是 agent，想知道何时用、加载后先干嘛](#-给-agent你被加载后第一步做什么)

## 🤖 给 agent：你被加载后第一步做什么

> **一句话自检**：你在把一个功能从 spec 多轮推到生产，且冒出"想多抽象一层 / 旧结论可能过期了 / health 200 想收工"的苗头 → 适用；单点 bugfix、一次性审查 → 不适用（见下方边界）。

你不需要"跑起来"。你是一组**行为契约**。加载我之后解决三件事：

### 1. 何时该激活我

命中下面任意一条就激活：

- 用户说"开个 MVP / 起 spec / 这功能要不要做 / **是不是太早** / **过度设计了吗** / 长任务编排"
- 任务是"修 X 然后部署 / 检查这个 workflow 完成则继续 / 框架稳了再进下一层"这类**反复审计-修复-部署-实测-落盘**的多轮推进
- 你刚 `/compact` 续会话或被心跳唤醒，拿到一句"某功能还没部署"的**二手状态**就准备动手

**不要激活**（去别处）：单一 bugfix→debug · 纯一次代码审查→review · 纯委派一轮→`agent-delegate`（我是它的调用方）· 写 skill 本身→`skill-creator`。

> 以上是判断场景；实际触发匹配以 SKILL.md frontmatter `description` 为准（`premature`/`三道闸` 在 body 不是触发词），见 INSTALL.md。

### 2. 加载后第一个动作 = 过闸，不是写代码

对每一个"想多做一层 / 想加抽象 / 想建框架"的冲动，当场念这条**固化口令**（SKILL.md §0 原文）：

> 每个"想多做一层"的冲动，同时过三道闸——(a) 要消费的信号此刻存在吗？(b) 生产数据用预设阈值证伪你了吗？(c) 用户拍板要做吗？**仪式可换，三道闸不可省。**

| 闸 | 你的第一动作 | 判停信号（喊不出 = 不成立） |
|---|---|---|
| **闸一 premature 挂 X** | 当场说出"要消费这层抽象的那个信号 X 是什么、它此刻存不存在" | 能写出缺的 X 且 X 当前**确实不存在（可核验）**；喊不出 X = premature 不成立，停手 |
| **闸二 真数据探针** | spec 假设"数据里有某分布"时，先**承诺量化阈值**，再跑一条最小聚合查询，只看统计不看原文 | 真数据对照**预设**阈值得 pass/fail；"跑个数看看"不算闸门 |
| **闸三 用户拍板** | 进开发/部署/路线分裂时，压成"带推荐+逃生口的选项"问用户（Claude Code 用 `AskUserQuestion`，其他 runtime 用各自交互） | 用户明确选定；**三方一致也仍要过这关**，AI 不替用户收敛 |

**判太早后默认动作不是放弃**，是切"现在能闭合的最小硬核子集"：复用现有字段、不新建外部系统、只留一条 trait 缝、**不预造第二实现**，余下拆成后续 spec。

### 3. 我怎么改变你的应答模式（before / after）

| 场景 | 加载我之前的你 | 加载我之后的你 |
|---|---|---|
| 用户："把这块抽象成通用框架，以后扩展方便" | 顺着"以后方便"就建第二套实现、加 plugin 接口、为不存在的第二种场景预留扩展点——一个没人用的空框架 | 挂闸一反问："要消费这个框架的第二个场景**此刻存在吗**？不存在→premature，只留一条 trait 缝，先切最小硬核子集，其余拆后续 spec"，并 `AskUserQuestion` 让用户拍板 |
| 审计回来：A 一家说"某外键索引会劣化查询"，置信度标得很高 | 收到 high-confidence blocker 就直接信，照着改 schema、加 index | 按 B4 亲核否决：单方独占→查真 schema 发现根本**没这个 index**，上生产只读探针实测延迟正常→**直接否决这条 blocker**。功劳是"亲核"不是"收了报告" |
| 改完代码、跑了部署脚本，health 200 | 认定"进程活着 = 上线成功"，宣布交付就去做下一个 | 认"health 200 只证明进程活着，不证明新功能生效"，跑端到端黑盒真路径实测——直查 DB / 调真接口断言新功能确实通电（不是进程活着），测完即删，再留观察窗 |

三道闸之外还有长程**横切纪律**（stale 免疫 / 后台派工不阻塞 / 预埋待审点自我证伪）和完整骨架（主循环 / 异构审计收敛 / 部署定序 / 落盘）→ **[SKILL.md](./SKILL.md)**。

## 👤 给人类：它治什么病、凭什么有效

### 它解决两类长程翻车

- **过度设计**：太早抽象、为不存在的需求建框架、铺一堆没人用的扩展点。
- **长程失稳**：多轮迭代后偏离真相、信仰自己的旧结论、health 200 就当上线成功。

### 凭什么有效：三道可证伪的闸

| 闸 | 做什么 | 防什么 |
|---|---|---|
| **premature 闸** | 用一个**具体缺失信号 X** 挂住"是不是太早"，喊不出 X 就不算太早，只是偷懒 | 防"凭感觉觉得该往下走"——没有 X 不许继续 |
| **真数据探针** | **先承诺量化阈值，再看数**，一条最小聚合查询只看统计 | 防"跑个数字事后找理由继续做" |
| **用户拍板** | 判停权在人手里，**AI 不替代收敛**，三方一致只降低拍板成本 | 防 AI 自我说服"已经够好了" |

在三道闸之上：**异构多方审计**（让跟宿主不同家族的模型来找盲区）驱动推进、**亲核源码否决**而非信仰任何一方报告（含否决自己）、**严格部署定序**（schema 先于代码 → dry-run → 只读探针 → 端到端实测 → 观察窗）保证交付不翻车。

> ⚠️ 别把仪式当因果：跑了三方审计**不等于**不会过度设计。起作用的是三道闸（尤其闸一挂具体 X），审计只是推进引擎。

### 我要先装一堆东西吗？不用

LTO 依赖的是**接口**不是具体实现。**最高 ROI 的硬核零依赖，拷过去就能用**；三个插槽按需装配升级：

| 插槽 | 零配置降级（0 安装） | 完整版 |
|---|---|---|
| **异构审计** | 当前 agent 起原生 subagent 多视角、不共享上下文（同模型家族故对抗性弱，须声明） | 装 `agent-delegate`，真异构三方（codex / pi / agy 等不同模型家族交叉诊断）；派工前对每个 runner 跑 smoke，结论写"实际用了 N 家"——不把理论三家当实测三家 |
| **记忆落盘** | `docs/decisions/` ADR + `MEMORY.md` 索引 | 接 `memory-flow` 或任何兼容 `experience_write`/`experience_search` 的后端，得语义检索+衰减+版本链 |
| **派工调度** | agent 原生 subagent 机制 | 装 `agent-delegate`，统一接口多 runtime 派工+回收（各家落地机制仍不同，见 cross-runtime-host-notes） |

**0 安装就覆盖最高 ROI**：三道闸、核验否决、stale 免疫、部署定序铁律——哪怕单 agent、无记忆库、无异构 runtime，照这几条做就能避开过度设计和长程翻车。降级矩阵全文 → **[SKILL.md §5](./SKILL.md)**。

## 安装

把 `long-task-orchestration/` 整个目录（含 `references/`）放进你 agent 的 skills 加载路径，能读到 SKILL.md 并命中触发场景即生效，不需要重启或装包。各 agent 路径惯例、三档插槽装配、references 项目特化替换 → **[INSTALL.md](./INSTALL.md)**。

## 跨 runtime（谁当宿主都能跑）

LTO 是 runtime-agnostic 的：主文件只写"为什么委派、收敛怎么判停、何时停、停了干嘛"的能力动作，派工实现一律走插槽降级路径，**不重述某一家 CLI 的 runner/tmux/quirk**。各家当宿主的差异（沙箱 / timeout / 启动方式）→ [`references/cross-runtime-host-notes.md`](./references/cross-runtime-host-notes.md)。

## 不适用（边界）

| 场景 | 走哪里 |
|---|---|
| 单一 bugfix | debug skill |
| 纯一次性代码审查 | review skill |
| 只委派一轮给另一个 runtime | `agent-delegate`（LTO 是它的调用方，不是替代） |
| 写 skill 本身 | `skill-creator` |
| 纯跑一条部署命令 | 直接走各自部署脚本，不需要整套编排 |
