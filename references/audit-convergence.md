# 异构审计收敛 — 轮次记账模板

> 主文件 §3 的执行细节。每一轮审计回来后填这张表，blocker 计数单调非增才算在收敛。

## 一、每轮记账表

| 轮次 | 审计对象 | HIGH | CRITICAL | minor | 本轮处置 | 计数趋势 |
|---|---|---|---|---|---|---|
| R1 | spec v0 | 3 | 5 | … | 修 X/Y/Z | 起点 |
| R2 | spec v1 | 2 | 1+2 | … | 修 …，否决 agy 性能 blocker | ↓ |
| R3 | spec v2 | 1 | 1 | … | 修最后两点 | ↓ |
| R4 | spec v2' | 0 | 0 | 3 | 全 minor 入 backlog | ✅ 收敛 |

**收敛判定**：`HIGH+CRITICAL` 单调非增，末轮 → 0 或仅剩 minor 且无新增 HIGH。

## 二、逐 blocker 分档处置（不投票）

每个 blocker 一行，标收敛形态 + 档位 + 结论：

```
[blocker] <一句话描述>
  收敛形态: 三方一致高置信 / 两方+一方漏 / 三方矛盾 / 单方独占
  档位:     确定 / 需核验 / 裁决 / 否决
  核验:     <亲核了什么源码:行号 / 什么数据>
  结论:     采纳(怎么修) / 否决(证伪依据)
```

**实证记录**（以一次真实的 spec 审计为例，演示「分档不投票 + 亲核否决」范式；细节已脱敏为中性示例）：
- 审计方A「某外键索引会劣化查询」→ 单方独占 → 亲查 schema 发现无此 index + 生产实测延迟 0.19s 正常 → **否决**（单方核不住）。
- 审计方B「强制路径加方案A」→ 单方建议 → 核验强制路径必命中某权威字段、方案A 在此退化成 no-op 且现状更安全 → **否决**。
- 审计方C「外键引用未去重 / 未绑实际记录」→ 两方收敛 → 亲核代码确认 → **采纳**，加去重集合 + 用 INSERT…SELECT 绑真实记录。
- 审计方A「存量无伴生对象的行走降级分支会空转」→ 单方高置信 → 亲核降级分支真值表，确认某字段为 NULL 时退化成 FALSE → **采纳**，降级前兜底插入一条基线记录。

## 三、反弹处理

- 修 A 又冒出 B（计数反弹）→ **暂停，回退 debug，重审上一轮**。不靠「再硬修一版」推。
- 连续 2 轮不降 → 怀疑审计标准或需求本身，回头质疑前提，别在错误前提上继续修。

## 四、预埋待审点（自我证伪）

起草 spec 时，把自己嗅到「可能空转 / 可能接不上」的点，显式写进 spec 的「待审点」清单，让三方**严判**而不是替自己圆场。

实证：某功能 spec 第一轮特意让三方严判自己预埋的待审点（如「某方案的隐藏字段会不会让降级空转」「低频下接通有无真实价值」「连续多次 premature 判定是否成立」）。三方 100% 判方案空转 → 升级到更健壮的实现。
